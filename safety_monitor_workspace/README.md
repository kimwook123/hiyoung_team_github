
## 14. 입력 / 로그 운영 정책

현재 입력과 로그는 아래 정책으로 동작합니다.

### 14-1. 영상 파일 / 스트림 선택 정책

- 영상 파일 경로는 `config.py`에 직접 적지 않습니다.
- 영상 파일과 스트림 주소는 Flutter GUI에서 선택합니다.
- Python은 GUI가 저장한 `logs/source_state.json`을 읽어 현재 입력 대상을 결정합니다.
- 카메라만 예외적으로 `config.py`의 `INPUT_MODE = "camera"`, `CAMERA_INDEX`로 직접 설정합니다.

### 14-2. 로그 파일 생성 정책

- 영상 파일은 파일 이름 기준으로 로그 파일을 만듭니다.
  - 예: `1.mp4` -> `logs/1_event_log.txt`
- 스트림은 `logs/stream_event_log.txt`를 사용합니다.
- 다른 영상 파일의 로그는 삭제하지 않고 보존합니다.

### 14-3. 같은 영상을 다시 분석할 때 정책

- 이미 로그 파일이 있는 영상을 다시 선택하면, 그 영상의 로그 파일은 새 분석 세션 기준으로 다시 씁니다.
- 즉 현재 선택한 영상의 기존 로그는 읽어서 이어 붙이지 않습니다.
- 대신 다른 영상의 로그 파일은 그대로 남겨둡니다.

예시:

- `video_a.mp4` 실행 -> `video_a_event_log.txt` 생성
- `video_b.mp4` 실행 -> `video_b_event_log.txt` 생성
- 다시 `video_a.mp4` 실행 -> `video_a_event_log.txt`는 새 결과로 덮어씀
- `video_b_event_log.txt`는 그대로 유지

### 14-4. 이벤트 로그 기록 정책

- 이벤트 로그는 **이벤트 1건당 1줄**로 관리합니다.
- 이벤트가 시작되면 바로 로그에 한 줄이 생성됩니다.
- 이벤트가 진행되는 동안 같은 이벤트 키 기준으로 같은 줄이 유지됩니다.
- 이벤트가 끝나면 같은 줄에 `end`, `end_frame`, `duration`, `clip_path`가 채워집니다.
- 그래서 `START` 줄, `END` 줄이 따로 두 개 생기지 않습니다.

### 14-5. 시간 기록 정책

- 영상 파일 입력에서는 `start`, `end` 시간이 PC 현재 시간이 아니라 **영상 시간 기준**으로 기록됩니다.
- 예: `00:08.160`, `00:17.760`
- 스트림이나 카메라는 절대 시간 개념이 더 자연스러우므로 현재 시각 기준 표시가 더 적합할 수 있습니다.

### 14-6. GUI 반영 정책

- GUI는 로그 파일을 수동으로 따로 열지 않습니다.
- 현재 선택한 입력에 맞는 로그 파일을 자동으로 계산해서 읽습니다.
- GUI는 짧은 주기로 로그 파일을 다시 읽어서 진행 중인 이벤트를 화면에 빠르게 반영합니다.

### 14-7. CCTV / 스트림 실시간성에 대한 참고

현재 구조는 파일 기반 연동이지만, 다음 조건이 맞으면 CCTV/스트림에서도 충분히 실시간 모니터링 형태로 사용할 수 있습니다.

- 이벤트가 시작될 때 바로 로그에 반영될 것
- GUI가 짧은 간격으로 로그를 다시 읽을 것
- Python 모델 추론 속도가 충분할 것

즉 실제 체감 지연은 최종적으로 **모델 추론 속도(FPS)** 에 가장 크게 영향을 받습니다.


### 14-8. GUI 시작 시 자동 선택 정책

- GUI를 실행해도 이전에 열었던 영상 파일이나 스트림을 자동으로 다시 열지 않습니다.
- GUI는 항상 빈 상태로 시작합니다.
- 사용자가 영상 열기 또는 스트림 열기를 직접 눌렀을 때만 입력을 엽니다.


### 14-9. 입력을 중간에 바꿀 때 주의사항

- GUI에서 다른 영상 파일이나 스트림으로 바꾸는 것은 가능합니다.
- 다만 현재 Python 분석 파이프라인은 시작할 때 입력 대상을 한 번 읽고 계속 처리하는 구조입니다.
- 그래서 Python을 다시 시작하지 않은 상태에서 GUI만 다른 입력으로 바꾸면, GUI 화면과 Python 분석 대상이 달라질 수 있습니다.
- 현재 구조에서 가장 안전한 사용 방법은 **입력을 바꾸고 싶을 때 Python 분석도 함께 다시 시작하는 것**입니다.
- un_python_and_gui.bat로 다시 시작하면 새 입력 기준으로 분석을 맞출 수 있습니다.


### 14-10. 입력 변경 시 자동 재시작 정책

- GUI 모드에서는 현재 입력 소스 상태를 Python이 계속 감시합니다.
- 사용자가 GUI에서 다른 영상 파일이나 다른 스트림으로 바꾸면, Python은 현재 분석을 정리한 뒤 새 입력으로 자동 재시작합니다.
- 따라서 GUI 화면과 Python 분석 대상이 서로 다른 상태로 오래 어긋나지 않도록 설계되어 있습니다.
- 입력 변경 직후에는 현재 이벤트를 정리하고 새 파이프라인을 여는 짧은 전환 시간이 있을 수 있습니다.
