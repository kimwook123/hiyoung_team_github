# AI_RULES.md

## 기본 작업 원칙
- 전체 프로젝트를 매번 다시 스캔하지 말 것. 현재 작업과 직접 연결된 폴더와 파일부터 최소 범위로 확인한다.
- 변경 전에는 5줄 이내의 짧은 계획을 먼저 적고 시작한다.
- 수정 파일 수를 최소화한다.
- 불필요한 대규모 리팩토링을 하지 않는다.
- 기존 실행 흐름을 임의로 바꾸지 않는다.
- 확실하지 않은 내용은 추측하지 말고 `확인 필요`로 표시한다.
- 작업 결과 보고는 간결하게 한다.

## 실행 및 검증 관련 규칙
- 빌드 실행, 앱 실행, 빌드 테스트는 사용자가 직접 수행하므로 AI가 자동으로 수행하지 않는다.
- 장시간 학습 실행, 대용량 다운로드, 무거운 모델 학습 실행은 사용자 확인 없이 하지 않는다.
- 영상 전체 재처리, 스트림 장시간 연결, 대형 가중치 교체 같은 무거운 검증은 먼저 사용자 확인을 받는다.

## Python 백엔드 수정 규칙
- `safety_ai_monitor/main.py`의 파이프라인 조립 순서를 이유 없이 바꾸지 않는다.
- 모델 경로, 데이터 경로, 결과 경로를 새로 하드코딩하지 않는다.
- `confidence threshold`, `class id`, `model path`, ROI 같은 설정값은 가능하면 `config.py` 한 곳에서 관리한다.
- 모델 추가 시 `DetectionModel` 공통 인터페이스와 `DetectionResult` 포맷을 유지한다.
- 룰 추가/수정 시 `EventFilter`가 `START/ACTIVE/END`를 관리한다는 점을 깨지 않도록 한다.
- `PersonTracker`는 현재 `person` 클래스 이름에 의존하므로, 클래스명 체계 변경 시 연관 영향도 함께 확인한다.

## Flutter GUI 수정 규칙
- Python과 Flutter 간 파일 입출력 구조를 바꿀 경우 양쪽 호환성을 함께 검토한다.
- 추론 결과 포맷이나 로그 텍스트 포맷을 바꿀 경우 `event_log_item.dart`, `event_log_service.dart`, 오버레이/리스트 UI 영향도까지 같이 확인한다.
- 현재 GUI는 `source_state.json`을 쓰고 로그 파일을 polling 방식으로 읽으므로, 이 규약을 바꿀 때는 기존 로그 조회 UX가 깨지지 않게 한다.
- 스트림 모드와 영상 파일 모드의 동작 차이(`replay clip`, `returnToLive`)를 유지한다.

## 경로 및 파일 통신 규칙
- `safety_ai_monitor/logs/`는 Python과 Flutter 사이의 공유 통신 영역으로 간주하고, 파일명과 의미를 신중히 바꾼다.
- `ui_bridge.json` 구조를 바꾸면 Flutter 쪽 탐색 로직과 하위 호환성(`video_path` fallback)도 같이 점검한다.
- `source_state.json`은 GUI 모드의 입력 제어 기준 파일이므로, 비어 있는 상태와 변경 감지 방식까지 고려한다.

## 확장 설계 규칙
- 위험상황 감지, 안전모 탐지, ROI 침범 감지는 룰 단위로 확장 가능하게 유지한다.
- 새 모델을 붙일 때는 “모델 프레임워크”보다 “공통 Detection 포맷으로 정확히 변환되는지”를 우선 확인한다.
- 다중 모델 비교 기능을 추가하더라도 기존 단일 모델 실행 경로를 먼저 깨지 않게 한다.
- 성능 측정 기능을 넣더라도 실시간 추론 루프를 과도하게 막지 않도록 한다.

## 이 프로젝트 전용 금지사항
- `NoHelmetRule`이 기대하는 클래스명(`person`, `helmet`)을 확인 없이 바꾸지 않는다.
- `LogEventHandler`의 한 줄 로그 형식을 확인 없이 변경하지 않는다.
- `logs/clips` 저장 규칙을 바꾸면서 Flutter의 `clip_path` 사용 여부를 확인하지 않은 채 배포하지 않는다.
- Windows 배치 스크립트의 상대 경로 규칙을 확인 없이 변경하지 않는다.
- 현재 존재하는 사용자 변경사항이나 가중치 파일 변경(`best.pt`)을 임의로 되돌리지 않는다.

## 이 프로젝트 전용 권장사항
- 작업 시작 전 관련 진입 파일을 먼저 본다.
  - 백엔드: `config.py`, `main.py`, `core/pipeline.py`
  - GUI 연동: `core/ui_bridge.py`, `lib/services/app_link_service.dart`, `lib/models/event_log_item.dart`
- 모델 교체 작업 시 확인 순서를 지킨다.
  1. `MODEL_TYPE` 분기
  2. 가중치 경로
  3. 출력 클래스명
  4. 룰 호환성
  5. 로그/GUI 영향
- 로그나 이벤트 포맷을 바꾸는 작업은 Python과 Flutter 파일을 같이 검토한 뒤 최소 범위로 수정한다.
- 발표/포트폴리오용 기능을 추가할 때는 “입력 -> 탐지 -> 이벤트 -> 로그/클립 -> GUI 표시” 흐름을 유지하며 설명 가능성을 높이는 방향을 우선한다.

## 확인 필요 항목 처리 규칙
- 코드에서 직접 확인되지 않은 기능은 문서에 단정하지 않는다.
- 현재 저장소에 없는 학습 코드, 배포 코드, 이미지 입력 경로, ONNX 추론은 필요 시 별도 확인 대상으로 남긴다.
